# Workspace audit — 2026-11-02

Scope: the whole repository, not just the dashboard. Four questions were asked and
each is answered with a measurement rather than an impression: does the workspace
meet its own declared standards and the course's requirements; is the analysis and
its code up to a defensible standard, and does it answer the four research
questions; are the figures and the web interface readable and correctly chosen;
what else is wrong.

The previous two audits (`Project_Audit_2026-11-02.md`, `Dashboard_Review_2026-11-02.md`)
are unchanged and still stand. This one found things neither covered, mostly in the
printed figure layer and in the traceability of the metrics files.

## 3. Analysis and code

### 3.1 Two claims that the artefacts could not support

| Finding | Severity | Resolution |
|---|---|---|
| `models.json` held no record of the train/test split. The proposal promises "a time-based split so that later months are never used to fit earlier ones", and the only evidence was a `print` on stdout. Worse, the field that looked like it held the boundary (`risk.holdout_start`) actually held the **last training date**, a different number | **P0** | `risk.split` now records `requested_start`, `actual_test_start`, `train_last_date` and a `fallback_to_chronological_80_20` flag. Stage 06 and the modelling notebook print it; a fallback is now visible instead of implied |
| `sensitivity.delta` was exactly `0.0` on all five statistics, because the fixture's years are 2019, 2023 and 2024 while the excluded years are 2020–2021. Nothing in the file said that zero rows had been removed, so `sensitivity_excluded_years.csv` read as "excluding the pandemic changes nothing" — a finding, not an artefact | **P0** | `excluded_rows` and a `note` are now written. When nothing is removed the note says the zero delta is arithmetic; stage 06 prints the same sentence |

### 3.2 A table that was silently empty

`attribution.carrier_table` defaulted to `min_flights=5000`. That floor is right for
the ten-year panel but wrong by an order of magnitude for the fixture, whose whole
attribution universe is 9,694 flights. The function returned a zero-row frame, and
`fig_carrier_bars` drew a fully labelled, completely empty axis — the kind of figure
that reaches a report because no error was raised.

Fixed on three levels:

1. The floor moved to `config/project.yaml` with a fixture override
   (`carrier_min_flights: 5000`, `carrier_min_flights_sample: 250`) and a comment
   that says the number applies to the attribution universe, not the panel.
2. `carrier_table` raises when nothing clears the floor, and names the largest
   carrier so the message points at the setting to change.
3. `fig_carrier_bars` raises on an empty table, and a new test covers both paths.

### 3.3 Thresholds that were duplicated

`dashboard.min_hour_flights` was read by the dashboard only, while the printed
cascade figure applied no floor at all and drew a 67% inherited share for an hour
holding 18 flights. A reader comparing the report figure with the dashboard saw two
answers to the same question. The key is now `viz.min_hour_flights`, read by both.

Yes at the level of method, no at the level of evidence.

| Question | Method present | Artefact | Blocked by |

- **The clustering is unstable at the fixture's scale** (mean ARI 0.49, verdict

- **The model barely ranks risk** (AUC 0.557 logistic, 0.544 boosting against a
  8.7% base rate). That is a legitimate finding for five observable factors, but it
  cannot be written as "we predict delay".

### Encoding choices worth defending in the report

- **Tile grid in print, choropleth on screen.** The proposal commits to a tile grid
  for national comparison because area distortion makes small dense states
  invisible. The dashboard uses a choropleth because airport bubbles need real
  coordinates. That is a difference of task, not an inconsistency, but the report
  has to say so — it is now written into `viz-guidelines.md` §6.
- **No dual axis where the two series are ratios of each other.** The cascade figure
  keeps its twin axis because the share is literally a part of the total; the
  dashboard hourly panel does the same. Everywhere else, one axis.
- **A highlighted maximum is only a statement if the bars differ.** Fig 03 now draws
  the all-carrier reference line, and adds a caption sentence when the spread is
  under 15%.
